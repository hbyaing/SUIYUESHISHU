# 玩偶白模使用规范

直接打开 [工作台](index.html)，导入原始 64 × 64 皮肤 PNG。选定 Alex 细臂或 Steve 粗臂后，依次检查正面、背面和左右两侧，再单独查看衣物外层。皮肤留在浏览器本地，工作台无需联网。

## 贴图判断

- 以选定手臂布局的 UV 范围为准。UV 范围之外的黑色、白色和其他像素都不参与贴图。
- 已映射区域按原像素贴合。全透明像素不显示，半透明保留透明度。可见的纯黑、纯白可能是衣物、鞋底、配饰或绘制工具填色。工作台将整片不透明的纯黑或纯白标为待核对，保留原色。
- 分别检查头部、躯干、左右臂、左右腿的底层与衣物外层。外层全透明时只显示底层。标准 PNG 只有这两套 UV。自定义第三层及以上需要作者提供独立图层或 UV 布局，普通 PNG 的颜色和边框无法说明它属于哪层。
- PNG 本身不记录粗臂或细臂。优先使用作者提供的模型类型。信息缺失时切换两种布局核对袖口、侧边接缝和手臂末端。

## 复用和导出

工作台从游戏的 `doll_part_head`、`doll_part_body` 和两个手臂模型读取网格，沿用现有的坐姿、头身比例、手臂角度和鞋袜外层。头部使用皮肤的标准外层，成然专属的凸起配饰由对应玩偶单独渲染。粗臂模式仅换用正确的四像素 UV，保留统一的玩偶轮廓。

选择手臂布局，导出 `doll_template_slim.json` 或 `doll_template_wide.json` 及 `doll_template.png`。导出的 JSON 是 Minecraft Java 方块模型格式，默认引用 `starcrowndoll:block/doll_template`。新玩偶可复用该网格，将 `skin` 指向原始 PNG。使用动态玩家皮肤时可复用游戏中的 `SelfDollRenderer`，由渲染器替换贴图资源。工作台预览是固定坐姿，动画仍由游戏渲染入口控制。

模型更新后在此目录运行 `python build.py`，重新生成离线页面。运行 `python build.py --check` 可检查页面是否对应当前模型。
