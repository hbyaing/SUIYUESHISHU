# 神格与背包侧栏 · 1.20.36

Minecraft Java 1.20.1 / Forge 47.4.0+ / Java 17。客户端与服务器均使用本版本。

## 空槽与操作

新增一格「神格」，沿用项目坐姿白模的主要可见结构线。图标只有灰色线条，所有面内与外部背景透明，直接显示槽位底色。生成工具为 `tools/generate-divinity-slot.py`。两个「如我所书」槽保留原书本线稿。

未安装 Curios 时，三个槽附在原版生存背包和创造模式的个人背包标签旁，不另开界面。小箭头折叠/展开三个槽；J 打开原版背包。开启配方书时侧栏移到背包另一边。支持普通点击、Shift 装备与取下，原版头盔槽、物品栏及 2×2 合成继续使用原菜单。

现有五种玩偶都能放进头盔槽或神格槽；神格中的玩偶沿用头顶渲染、动画和神性判定。两个位置总共只允许一个玩偶，同款也互斥。普通头盔可与神格玩偶同时佩戴。常规点击、右键佩戴和 Shift 装备都检查互斥；外部代码强行写入两个玩偶时只启用一个神性，下一次玩家 tick 将冲突物品退回物品栏，放不下则掉落。

成然异常移除保护记录原装备位置，恢复到原头盔槽或神格槽；神格恢复不会覆盖普通头盔。玩家正常从槽位取下会解除保护。

## Curios 切换

Curios 是可选依赖，支持 1.20.1 的 5.14.1+ / 5.x。安装后，原版背包不追加独立槽，独立侧栏、按钮、J 键注册和独立装备同步/掉落逻辑停用，改用 Curios 原生的 `starcrowndoll_divinity` 一格和 `starcrowndoll_as_written` 两格。

使用 Curios 的原生界面、显示开关和物品操作。关闭神格的原生显示开关只隐藏头顶模型，不解除装备能力。原生 Curios 的 Shift 装备优先级可能先选择头盔槽，可直接把玩偶放入神格槽。

首次安装自动迁移独立装备。独立 capability 在 Curios 模式下只保留不参与装备判定的存档快照；移除 Curios 后用其恢复。重新安装 Curios 时用最近的独立存档替换旧的休眠快照，防止已经取走的装备再次出现。

独立模式死亡遵循 `keepInventory`，正常死亡掉落一次；Curios 模式交由其原生掉落流程处理。

## 如我所书

当前仅预留两个槽，尚未添加饰品本体、配方或能力。正式包不允许纸张装备；纸张只是隔离 QA 环境中的测试物品。

未来物品加入 `starcrowndoll:as_written_accessories` 标签即可接入，也识别旧 `curios:starcrowndoll_as_written` 标签。独立模式每格最多一件；Curios 模式遵循其原生物品堆叠规则，独立槽不模拟第三方 Curios 回调。

## 验证范围

- 64 项服务端 GameTest 通过：五种玩偶、25 种组合双向互斥、普通头盔共存、原版菜单点击与合成、成然神格恢复/正常取下、存档与死亡掉落。
- 正式映射 Forge 47.4.26 隔离客户端：无 Curios 的生存/创造背包、三槽图标、折叠展开、网络装备/取下、鼠标物品数量与 NBT、头顶玩偶渲染。
- Curios 5.14.1 隔离客户端：原生三槽、独立槽停用、25 种组合双向互斥、原生菜单取下成然解除保护、普通头盔与头顶玩偶共存。
- 同一隔离存档：独立模式 → 安装 Curios → 移除 Curios → 清空独立装备 → 重新安装 Curios，核对 NBT、书槽数量及不恢复旧快照。

截图与检查结果保存在同名目录。测试模组源码位于 `tools/qa/runtime`，不打入正式 JAR；测试没有修改用户正式游戏目录或存档。
