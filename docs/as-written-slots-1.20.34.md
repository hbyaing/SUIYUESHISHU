# 如我所书饰品栏 · 1.20.34

Minecraft Java 1.20.1 / Forge 47.4.0+ / Java 17。实机验收使用 Forge 47.4.26、Curios Forge 5.14.1+1.20.1。

## 玩家使用

安装本模组及 Curios 后，所有玩家进入世界即有两个名为「如我所书」的功能槽。按 Curios 默认键 G，或用背包中的 Curios 按钮打开；有按键冲突时可在控制设置中修改。两格使用 Curios 原生布局，不额外生成外观槽，不需要通过道具解锁。

空槽图标以用户提供的蓝色书本贴图为依据，保留可辨识的书本外框、书脊、页边、书签、封面双圆环和中心星芒，以灰色线稿绘制并隐藏其他底色、反光和细碎纹理。用户红线仅用于提示主要结构；圆环和书页边缘依据原书整理。64×64 图标的所有线条均位于原书透明轮廓之内。去除棋盘背景的参考书图保存在 `as-written-slots-1.20.34/book-source.png`，线稿生成脚本为 `tools/generate-as-written-slot.py`。

本版本只提供空槽，不提供「如我所书」饰品本体、配方或能力。现有玩偶仍按原来的头部穿戴方式生效。Curios 是可选依赖：安装时支持 5.14.1 至 6.0 之前的版本；未安装时不提供这些槽位，模组仍可正常加载。联机时客户端与服务器需同时安装对应模组。

## 后续饰品接入

槽位标识：`starcrowndoll_as_written`，每位玩家基础数量为 2。根数据位于 `data/starcrowndoll/curios/slots/` 与 `data/starcrowndoll/curios/entities/`，普通玩家和已有存档均通过 Curios 的玩家绑定获得槽位，数量不靠登录事件累加。

可装备物品使用 `curios:starcrowndoll_as_written` 标签。当前标签已为未来 `starcrowndoll:as_written` 物品预留可选条目；该物品尚未注册，缺失时不会阻止标签加载。后续制作饰品时还需单独实现其能力。本次沿用 Curios 标准标签校验器，不修改其他模组的槽位及通用 Curios 规则。

## 验收

正式包与独立 QA 包通过离线 Gradle 构建。`AsWrittenSlotsQa` 仅编入 QA 包，通过工作目录中的 `enable-as-written-slots-qa` 文件启用，不进入正式 JAR。

隔离的 Forge 实际客户端使用复制的测试世界及新的离线测试玩家，验证：

- 服务端和客户端都有两个可见的空槽，且没有额外外观槽。
- 两个槽均拒绝石头；未来饰品本体与能力未纳入本次验收。
- Curios 能力数据写入并读取 NBT 后，槽位数仍为 2。
- 真实 Curios 按键打开原生菜单，菜单实际包含两个对应的功能槽；已保存游戏截图。
- 另一份不含 Curios 的隔离客户端正常进入测试世界并退出，确认可选依赖不影响原有模组加载。

上述验证不会修改正式实例或用户存档。它不等同于未来饰品的装备、死亡掉落或能力验收。
